**OWASP (Open Web Application Security Project)** merilis daftar 10 risiko keamanan aplikasi web paling kritis di dunia. Di peringkat teratas bertengger dua kerentanan paling mematikan: **Broken Access Control** dan **Injection**.

---

## 1. Broken Object Level Authorization (BOLA / IDOR)

**IDOR (*Insecure Direct Object Reference*)** terjadi ketika aplikasi menerima identifier objek dari pengguna (misal: ID dokumen di URL) tanpa memverifikasi apakah pengguna yang sedang login benar-benar pemilik sah dari objek tersebut:

```text
// SKENARIO IDOR RENTAN:
// Pengguna A (ID: 45) login, lalu mengubah URL browser menjadi:
GET /api/v1/invoices/1092  <-- Tagihan milik Pengguna B (ID: 88)!

// Backend yang ceroboh hanya mengeksekusi:
SELECT * FROM invoices WHERE id = 1092; // KEBOCORAN DATA!
```

### Solusi Pertahanan IDOR:
```javascript
// Validasi Kepemilikan Data (Context-Aware Ownership Check)
export async function getInvoice(req, res) {
  const invoiceId = req.params.id;
  const currentUserId = req.user.id; // Diambil dari JWT terverifikasi

  const invoice = await db.invoices.findFirst({
    where: {
      id: invoiceId,
      userId: currentUserId // HANYA ambil jika invoice milik user yang sedang login!
    }
  });

  if (!invoice) {
    return res.status(404).json({ success: false, message: "Faktur tidak ditemukan" });
  }

  res.json({ success: true, data: invoice });
}
```

## 2. Anatomi SQL Injection (SQLi)

**SQL Injection** terjadi ketika input mentah dari form atau parameter URL digabungkan langsung (*string concatenation*) ke dalam string perintah SQL:

```javascript
// ❌ KODE SANGAT BERBAHAYA (VULNERABLE):
const sql = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`;

// Jika Hacker memasukkan username: admin' OR '1'='1' --
// String query berubah menjadi:
// SELECT * FROM users WHERE username = 'admin' OR '1'='1' --' AND password = '...'
// Query mengevaluasi TRUE dan membocorkan akun admin tanpa password!
```

### Solusi Mutlak: Prepared Statements / Parameterized Queries
```javascript
// ✅ KODE AMAN (SECURE):
// Database engine memisahkan instruksi SQL dari data variabel secara biner
const [rows] = await db.execute(
  'SELECT * FROM users WHERE username = ? AND password = ?',
  [username, passwordHash]
);
```

function vulnerableSearch(inputUsername) {
  console.log(\`🔍 [VULNERABLE SQL] Input diterima: "\${inputUsername}"\`);

  const rawQuery = \`SELECT * FROM users WHERE username = '\${inputUsername}'\`;

  if (inputUsername.includes("' OR '1'='1") || inputUsername.includes("' OR 1=1")) {

// 2. ENGINE AMAN (Prepared Statements Parameterized)
function secureSearch(inputUsername) {
  console.log(\`🔒 [SECURE PREPARED STATEMENT] Input: "\${inputUsername}"\`);
  console.log("   Perintah SQL: SELECT * FROM users WHERE username = ?");
  console.log(\`   Parameter Binding: [? = "\${inputUsername}"] (Diterlakukan murni sebagai teks data)\`);

  return usersTable.filter(u => u.username === inputUsername);
}

// --- PENGUJIAN PERBANDINGAN KEAMANAN ---

console.log("\\n=== 2. MENYERANG ENGINE DENGAN PREPARED STATEMENT ===");

<Callout type="tip" title="Mass Assignment Vulnerability">
  Selain SQLi, waspadai kerentanan **Mass Assignment**: jangan pernah menulis `User.create(req.body)`. Hacker dapat menyisipkan `role: 'ADMIN'` atau `isVerified: true` di JSON payload request. Selalu filter field yang diizinkan (*Whitelist DTO*).
