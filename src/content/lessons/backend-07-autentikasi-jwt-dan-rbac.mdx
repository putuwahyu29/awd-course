## 1. Password Hashing: Mengapa Plaintext & MD5 Dilarang Keras?

Password **tidak boleh pernah disimpan dalam bentuk teks biasa (plaintext)** atau algoritma usang seperti MD5/SHA1 (karena rentan serangan *Rainbow Table* dan *GPU Brute-force*).

Gunakan algoritma lambat berbasis memori yang dirancang khusus untuk password: **Argon2id** (pemenang Password Hashing Competition) atau **Bcrypt**:

```javascript
import bcrypt from 'bcrypt';

const SALT_ROUNDS = 12;

// Saat Registrasi Pengguna
export async function hashPassword(plainPassword) {
  return await bcrypt.hash(plainPassword, SALT_ROUNDS);
}

// Saat Login Pengguna
export async function verifyPassword(inputPassword, storedHash) {
  return await bcrypt.compare(inputPassword, storedHash);
}
```

## 2. Anatomi JSON Web Token (JWT) & Best Practices

JWT adalah standar terbuka (RFC 7519) untuk mentransmisikan klaim identitas secara aman antara pihak-pihak sebagai objek JSON yang ditandatangani secara kriptografis.

### Rekomendasi Arsitektur Token Produksi:
1. **Access Token (Masa Aktif Pendek: 15 Menit)**: Berisi `userId` dan `role`. Digunakan untuk mengakses protected API endpoints.
2. **Refresh Token (Masa Aktif Panjang: 7 Hari)**: Disimpan di cookie bertipe `HttpOnly; Secure; SameSite=Strict` untuk mencegah pencurian token melalui serangan Cross-Site Scripting (XSS). Disertai mekanisme *Token Rotation*.

## 3. Role-Based Access Control (RBAC) Middleware

RBAC memastikan bahwa hanya pengguna dengan wewenang tertentu yang dapat mengakses endpoint tertentu (misal: hanya role `SUPERADMIN` atau `EDITOR` yang dapat menghapus artikel):

```javascript
export const requireRoles = (...allowedRoles) => {
  return (req, res, next) => {
    if (!req.user) {
      return res.status(401).json({ success: false, message: 'Unauthenticated' });
    }

    if (!allowedRoles.includes(req.user.role)) {
      return res.status(403).json({
        success: false,
        message: `Forbidden: Hak akses role '${req.user.role}' tidak mencukupi`,
      });
    }

    next();
  };
};

// Contoh Penggunaan di Route
// app.delete('/api/users/:id', authenticateJWT, requireRoles('SUPERADMIN'), deleteUserHandler);
```

  return btoa(str).replace(/=/g, "").replace(/\\+/g, "-").replace(/\\//g, "_");

<Callout type="warning" title="Peringatan Keamanan Kritis">
  Jangan pernah menyimpan data sensitif seperti password, nomor kartu kredit, atau API Secret Key di dalam payload JWT. Payload JWT **hanya di-encode dengan Base64**, bukan dienkripsi secara rahasia, sehingga siapapun yang memegang string token dapat membaca isi payload tersebut!
