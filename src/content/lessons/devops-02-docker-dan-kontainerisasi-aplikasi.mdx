Pernahkah Anda mendengar keluhan klasik: *"Tapi kodenya jalan lancar di laptop saya, kenapa pas dideploy di server error?"* (*"It works on my machine!"*). **Docker** memecahkan masalah ini dengan mengemas aplikasi beserta seluruh dependensinya (Node runtime, library C, konfigurasi OS) ke dalam satu unit mandiri bernama **Container**.

---

## 1. Virtual Machine (VM) vs Docker Container

```text
┌──────────────────────────────────────┐     ┌──────────────────────────────────────┐
│       VIRTUAL MACHINE (VM)           │     │           DOCKER CONTAINER           │
├──────────────────┬───────────────────┤     ├──────────────────┬───────────────────┤
│   App A (Node)   │    App B (Python) │     │   App A (Node)   │   App B (Python)  │
│  Libs / Binaries │   Libs / Binaries │     │  Libs / Binaries │  Libs / Binaries  │
│  Guest OS (Ubuntu│  Guest OS (Alpine)│     ├──────────────────┴───────────────────┤
├──────────────────┴───────────────────┤     │           Docker Engine              │
│            Hypervisor                │     ├──────────────────────────────────────┤
├──────────────────────────────────────┤     │         Host Operating System        │
│        Host Operating System         │     ├──────────────────────────────────────┤
│          Hardware Server             │     │          Hardware Server             │
└──────────────────────────────────────┘     └──────────────────────────────────────┘
```

- **Virtual Machine**: Mengemulasikan seluruh sistem operasi lengkap (*Guest OS*). Berat (memakan puluhan GB) dan lambat saat booting (menit).
- **Docker Container**: Berbagi *Kernel Host OS* secara langsung dengan isolasi *Namespaces* & *Cgroups*. Sangat ringan (MB) dan start dalam hitungan milidetik!

## 2. Anatomi Penulisan `Dockerfile` Produksi

Sebuah `Dockerfile` adalah instruksi bertahap untuk membangun sebuah *Docker Image*.

### Pola Multi-Stage Build (Memangkas Image dari 1.2GB ke 50MB):
```dockerfile
# =======================================================
# STAGE 1: Dependency & Build Stage (Membutuhkan toolchain)
# =======================================================
FROM node:22-alpine AS builder

# Pasang direktori kerja
WORKDIR /usr/src/app

# Salin hanya manifest package untuk memaksimalkan Docker Layer Cache
COPY package*.json ./

# Install dependensi secara deterministik
RUN npm ci

# Salin seluruh source code
COPY . .

# Eksekusi kompilasi build (misal: TypeScript / Vite / Astro)
RUN npm run build --if-present

# Hapus devDependencies agar folder node_modules bersih
RUN npm prune --production

# =======================================================
# STAGE 2: Minimal Production Runtime (Hanya artifact bersih)
# =======================================================
FROM node:22-alpine AS runner

WORKDIR /usr/src/app

# Set environment produksi
ENV NODE_ENV=production

# Praktik Keamanan: Jangan jalankan container sebagai ROOT!
USER node

# Salin hanya artifact yang telah dibersihkan dari Stage Builder
COPY --chown=node:node --from=builder /usr/src/app/node_modules ./node_modules
COPY --chown=node:node --from=builder /usr/src/app/dist ./dist
COPY --chown=node:node --from=builder /usr/src/app/package.json ./package.json

# Buka port aplikasi
EXPOSE 3000

# Perintah eksekusi utama
CMD ["node", "dist/server/entry.mjs"]
```

## 3. Pentingnya Berkas `.dockerignore`

Sebelum Docker membangun image, Docker CLI akan mengirim seluruh direktori lokal ke Docker Daemon (*Build Context*). Tanpa `.dockerignore`, folder lokal `node_modules` (yang mungkin berisi binary Windows) akan terkirim ke container Linux dan merusaknya:

```text
# .dockerignore
node_modules
dist
.git
.env
.env.local
*.log
npm-debug.log
.DS_Store
```

## 4. Perintah Esensial Docker CLI di Lingkungan Kerja

| Perintah | Fungsi | Contoh Penggunaan |
| :--- | :--- | :--- |
| `docker build` | Membangun Docker Image dari Dockerfile | `docker build -t my-app:v1.0 .` |
| `docker run` | Menjalankan kontainer baru dengan port mapping | `docker run -d -p 3000:3000 --name web-container my-app:v1.0` |
| `docker ps` | Melihat daftar kontainer yang sedang berjalan | `docker ps -a` |
| `docker logs` | Melihat log output dari dalam kontainer | `docker logs -f web-container` |
| `docker exec` | Masuk ke dalam terminal kontainer yang aktif | `docker exec -it web-container sh` |
| `docker stop` / `rm` | Menghentikan & menghapus kontainer | `docker stop web-container && docker rm web-container` |
| `docker system prune` | Membersihkan image/cache yang tidak terpakai | `docker system prune -af --volumes` |

<Callout type="tip" title="Docker Layer Caching">
  Docker mengeksekusi instruksi baris per baris. Jika suatu baris tidak berubah, Docker akan menggunakan cache dari memori. Oleh sebab itu, letakkan `COPY package*.json ./` dan `RUN npm ci` **sebelum** `COPY . .` agar instalasi dependensi tidak diulang setiap kali Anda mengedit satu baris kode JavaScript.
</Callout>
